## Migration Strategy

### Key Architectural Changes

#### 1. State Management
**Vite App:** Zustand store with client-side state
**Next.js App:** API routes + Server components + React Query/SWR

**Action Required:**
- Replace Zustand store calls with API fetch calls
- Implement React Query or SWR for data fetching
- Convert client components to use Next.js patterns

#### 2. Routing
**Vite App:** React Router with `useNavigate()`
**Next.js App:** File-based routing with `useRouter()` from `next/navigation`

**Action Required:**
- Replace all `useNavigate()` with `router.push()`
- Update all route paths to match Next.js structure
- Convert dynamic routes to bracket notation

#### 3. Data Fetching
**Vite App:** Direct Supabase client calls
**Next.js App:** API routes → Database queries

**Action Required:**
- All database calls must go through API routes
- Implement proper error handling
- Add loading states

## Risk Assessment

### High Risk Items

1. **Data Migration**
   - Risk: Data loss during migration
   - Mitigation: Keep Vite app running, gradual cutover

2. **Simulation State Management**
   - Risk: Complex state not properly migrated
   - Mitigation: Thorough testing, user acceptance testing

3. **Video Playback**
   - Risk: Video URLs or playback breaks
   - Mitigation: Test all video sources, fallback mechanisms

4. **Bravin Integration**
   - Risk: Scoring logic errors
   - Mitigation: Unit tests, compare results with Vite app

### Medium Risk Items

1. **Authentication Flow**
   - NextAuth vs Supabase auth differences
   - Session management

2. **Performance**
   - Potential slowdowns with API round-trips
   - Need for proper caching strategy
